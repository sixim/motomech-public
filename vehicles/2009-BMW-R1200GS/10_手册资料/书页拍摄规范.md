## 要改的，按收益排序

### 1. 背面透印 —— 一张黑纸解决（收益最高，成本最低）

实测：薄页（如 p50「Notes」）能清楚读出背面的反字，OCR 会把它当正文吃进去。

**做法：在当前页下面垫一张黑色卡纸。** 透印立刻消失。这是整份规范里性价比最高的一条。

### 2. 白平衡 —— 只有接线图会因此出错

实测（**全部 50 页**）：R/B 最小 **1.03**、中位 **1.51**、最大 **1.57**；
其中 **45/50 页超过 1.4**。中性纸应接近 1.0 —— 也就是绝大多数页偏暖约 50%，
只有 5 页接近中性（多半是那几页恰好光线不同）。

- 对**黑字**：无影响。这 50 页的数字我全部读出来了，没有一处含糊。
- 对**彩色接线图**：会出错。蓝线偏成灰绿，棕线与红线难分。
  读错一根线的后果，比读错一个数字严重。

**做法（任选其一）**：
- 用 iOS「备忘录 → 扫描文稿」或「文件 App → 扫描」：自带白平衡与透视校正，最省事
- 或在相机里锁定白平衡，先对一张白纸取基准
- 或白天靠窗用自然光拍（色温自然中性）

**接线图那几页务必用上面任一种**，正文页可以不管。

### 3. 光照均匀度

实测（**全部 50 页**）：四角亮度极差最小 **5.7**、中位 **32**、最大 **112**（满量程 255），
即**最坏的一页四角差 44%**。中位 13% 尚可，但长尾很重 —— 典型的单侧光源。

**做法**：左右两侧对称打光；或改用窗边散射自然光。不要用单只台灯斜打。

### 4. 手指与书脊弯曲 —— 一块玻璃同时解决

⚠️ **「手指入画」这一条撤回 —— 两轮都判错了，而且是同一个陷阱。**

第一轮我说 p43 有手指，监工复不出来；第二轮我改成 p17，第三轮监工指出
**那页的手是书里印着的照片**（Haynes 的操作图本来就大量是「手拿工具」的特写）。

**拍一本满是手部特写的书，「手指入画」在图像上和印刷内容长得一模一样。**
这个判据在这本书上不可靠，除非能同时看到手指压在页面边缘并遮住版心。
目前没有一页确证，**不作为已知问题**。

多页靠书脊侧有明显弯曲，
**弯曲是 OCR 分栏错乱的主因**（多栏正文被横向串成一行）。

**做法**：拿一块干净玻璃（相框玻璃即可）压平书页。
一次解决弯曲、页面不平、以及万一真有的手指入画。注意玻璃会反光 —— 光源不要正对。

### 5. 朝向

实测 p2 是横向（3295×2551），其余 49 页纵向。拍完顺手转正，
否则 OCR 对那一页基本无效。

## 拍完怎么入库

```bash
# 把新拍的 PDF 放进 raw/，然后：
bash tools/bookproc.sh
```

流水线会做 OCR、合并、导出带 `=== PAGE n ===` 标记的全文，
并**保留原图画质不变**（只加隐藏文字层）。

入库后务必核一次页码对齐：
```bash
motomech search "某个只在某页出现的词"
```
拿到页码后回原图看是不是那一页。**页码错位会让「回原图确认」这套机制整个失效**，
而它是本平台准确性的最后一道保险。

## 一条不要做的事

**不要做二值化、去噪、锐化之类的「增强」。** 接线图靠颜色区分线束，
任何增强都可能毁掉颜色信息。iOS 扫描模式做的透视校正和去阴影是安全的，到此为止。
